JOE RONG · 2026

打通

从救火到造流水线

01
两周。

一个设计需求从读 Spec 到可测试的 Demo，至少两周。

不是因为需求复杂——是因为每个环节都在排队。

设计等前端，前端等排期，排期等资源。
设计稿做完了，躺在那儿，没人能验证。

瓶颈到底在哪？

02

绕路

瓶颈在 Demo。必须等前端手写代码，大家才能看到效果。
这个环节吃人力、吃时间——而产出只是验证用。

那能不能跳过它？

我和后端一起做了 Figma-to-Code 平台。
设计师上传文件，平台自动读取、渲染、部署。
配合 Data Schema，灌入真实数据。

从两周，变成当天。

这个平台现在整个产品团队都在用。

03

意外发现

Figma Make 有时还原度很高，有时一塌糊涂。
我们反复调参，想找到那个"稳定输出"的开关。

Design Guideline
设计规范越精确
AI 输出越稳定
Global CSS
样式定义越完整
还原度越高

不是运气——是喂给它的规则够清晰。

04

反向

Guideline + CSS 保证了 Design → Code 的质量。

那能不能反过来？用 AI 生成设计？

我整理了 News Team 过去上百个设计文件，
提炼出专属 News 的视觉语言。

然后实验：设计师不画图，只写 Prompt。
Magazine Timeline Digest Card

Prompt → Design，跑通了。

05

继续推

Design → Code ✓  Prompt → Design ✓

链路还剩一个断点：Spec → Prompt

设计师看 Spec 时在想什么？
哪些信息关键？哪些约束影响方向？

我把这个思考过程拆解成 Skill——
AI 按设计师的思维模式提问、拆解，输出高质量 Prompt。

这部分还在 building，但逻辑已经跑通。

06

一条线

以前
Spec → 人读 → 人想 → 人设计 → 人写代码 → Deploy
2 周
现在
Spec → AI 拆解 → AI 设计 → AI 写码 → 自动部署
1 天

救火救着救着，发现自己在造流水线。

07

不只是提效

以前
执行者
拿到需求，画图，交付。
一个人的产能 = 一个人的产能。
线性增长。
现在
规则制定者
定义 Guideline、CSS、思考框架。
AI 按你的规则，批量生成。
指数增长。

你的产能不再是你画了多少图，
而是你建立的系统能生成多少图。

08

下一步

Design Guideline
不是文档——
是给 AI 的指令集
Global CSS
不是样式表——
是视觉语言的编码
Skill
不是流程图——
是思考方式的外化

我们不是在用 AI 替代设计师。
我们是在把设计师的能力，变成可复用、可放大的资产。

09

从救火到造流水线，
从解决问题到设计系统。

AI 没有替代我——
它放大了我。
