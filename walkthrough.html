一个设计需求从读 Spec 到可测试的 Demo，至少两周。

不是因为需求复杂——是因为每个环节都在排队。设计等前端，前端等排期，排期等资源。

设计稿做完了，躺在那儿，没人能验证。

瓶颈到底在哪？
02 · 绕路

瓶颈在 Demo

必须等前端手写代码、部署环境，大家才能看到效果。这个环节吃人力、吃时间——而产出只是验证用的，不是最终上线的代码。

我和后端一起做了 Figma-to-Code 平台。设计师上传文件，平台自动读取、渲染、部署。配合 Data Schema，灌入真实数据。

两周 → 当天

意外发现

Figma Make 有时还原度很高，有时一塌糊涂。我们反复测试，想找到"稳定输出"的开关。

Design Guideline

规范越精确，
AI 输出越稳定

Global CSS

样式越完整，
还原度越高

不是运气——是喂给它的规则够清晰。

能不能反过来？

我整理了 News Team 过去上百个设计文件，提炼出专属的视觉语言。

然后实验：设计师不画图，只写 Prompt。Magazine Timeline，Digest Card。

✓ Prompt → Design，跑通了
Design → Code
Prompt → Design
Spec → Prompt

继续推

Design → Code Prompt → Design

链路还剩一个断点：Spec → Prompt

设计师看 Spec 时在想什么？哪些信息是关键？哪些约束会影响方向？

我把这个思考过程拆解成一个 Skill——AI 按设计师的思维模式提问、拆解，最后输出高质量 Prompt。
